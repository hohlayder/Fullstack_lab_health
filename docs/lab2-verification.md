Интеграционные тесты применяли миграции к отдельным временным схемам настоящей PostgreSQL в `family_health_test`. Проверены:

- Создание, списки, чтение, PATCH и удаление четырёх основных сущностей, статусы `201`, `200`, `204`, заголовок `Location`.
- Сохранение через отдельную ORM-сессию и чтение заново созданным FastAPI-приложением.
- Каскадное удаление семьи, человека и назначения вместе с зависимыми записями.
- PK, FK, уникальность отметки, ограничения дат курса и `taken`/`taken_at` непосредственно в PostgreSQL.
- Ошибки `404`, `409`, `422`, откат конфликтующих изменений и работоспособность последующих запросов.
- Пустые и неизвестные поля, `null` в PATCH, очистка конца курса, недопустимые даты и времена.
- Повторная отметка «принято», отмена отметки и запрет принятого приёма за будущий день.
- Согласованность истории при изменении времени или курса назначения.
- Дневное расписание, фильтры семьи и человека, разделение отметок по датам, данные списка врача.
- Повторная загрузка демо без дубликатов и перезаписи существующих изменений.
- Обратимость миграции, CORS, health, OpenAPI, Swagger и ответ `503` без раскрытия сведений подключения.

## Проверка работающего HTTP-сервера

Сервер был запущен командой:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Через `Invoke-RestMethod` и `Invoke-WebRequest` проверены:

| Запрос | Результат |
| --- | --- |
| `GET /health` | `200`, `status=ok`, `database=postgresql` |
| `GET /openapi.json` | `200`, версия API `0.2.0` |
| `GET /docs` | `200` |
| `GET /api/v1/schedule?family_id=57894a99-7ce7-532f-8345-11c9fd1cfa20&day=2026-10-07` | Шесть приёмов, два приняты |
| POST семьи, человека, назначения и отметки | Четыре успешных создания со статусом `201` |

Временные записи HTTP-проверки удалены; демонстрационная семья сохранена. Проверочный Uvicorn остановлен.

- В рабочей базе остались **1 семья, 3 человека, 5 назначений, 6 отметок**.
- Расписание демо-дня снова вернуло шесть приёмов, два приняты.
- Повторный `alembic check` подтвердил соответствие схемы моделям.

Локальный кластер оставлен запущенным. `.env` с автоматически сгенерированным паролем, `.local` с данными и `.venv` исключены из Git, что отдельно проверено через `git check-ignore`.

# Близкие — напоминания о лекарствах для семьи

Учебный проект курса «Fullstack», первый семестр. Тема: **«Напоминания о лекарствах: расписание для семьи, напоминания, отметка „принято“, печать списка для врача»**.

Текущий этап — **лабораторная работа №1: интерфейс приложения и каркас frontend**. Реализованы экраны, клиентская маршрутизация, единое оформление, базовая адаптивность и демонстрационные данные. Лабораторные №2–5 пока запланированы.

## Назначение и сценарии

Приложение помогает одному пользователю просматривать назначения всей семьи, видеть ближайшие приёмы и готовить список лекарств для визита к врачу.

1. **Посмотреть план на день.** Открыть расписание, увидеть утренние, дневные и вечерние приёмы, при необходимости выбрать одного члена семьи.
2. **Открыть расписание близкого.** В разделе «Моя семья» выбрать карточку человека и перейти к его расписанию или лекарствам.
3. **Проверить назначения.** В разделе «Лекарства» посмотреть дозу, время, длительность курса и примечание.
4. **Отметить приём.** Нажать «Принять». Кнопка станет «Принято», обновятся счётчики и ближайшие напоминания. Повторное нажатие отменяет отметку.
5. **Посмотреть напоминания.** Открыть ближайшие неотмеченные приёмы и попробовать переключатели настроек макета.
6. **Подготовиться к врачу.** Выбрать человека в разделе «Список для врача» и нажать «Распечатать». В системном окне печати можно выбрать принтер или сохранение в PDF.

## Экраны и маршруты

| Экран | Маршрут | Содержание |
| --- | --- | --- |
| Расписание | `/schedule` | Прогресс за день, фильтр человека, приёмы по времени, пробная отметка «принято» |
| Моя семья | `/family` | Карточки трёх человек, статистика, переходы к их расписанию и назначениям |
| Лекарства | `/medications` | Таблица назначений, дозы, время, курсы, фильтр человека |
| Напоминания | `/reminders` | Ближайшие неотмеченные приёмы, демонстрационные настройки |
| Список для врача | `/doctor` | Выбор человека, предпросмотр списка, печать |
| Страница не найдена | Любой неизвестный адрес | Сообщение 404 и возврат к расписанию |

Адрес `/` перенаправляет на `/schedule`. Выбор человека хранится в параметре `?member=anna`, `?member=elena` или `?member=mikhail`: ссылку на его расписание можно открыть напрямую. Неизвестный идентификатор заменяется выбором по умолчанию.

## Стек и зависимости

- **React + TypeScript** — интерфейс и строгая типизация.
- **Material UI**, `@mui/icons-material` и Emotion — готовая библиотека компонентов, иконки и общая тема. Используются кнопки, карточки, таблицы, фильтры, переключатели, сообщения, прогресс и мобильная панель навигации.
- **React Router** — клиентские маршруты и переходы без перезагрузки страницы.
- **Vite** — сервер разработки и production-сборка; страницы загружаются отдельными модулями.
- **Manrope / Fontsource** — локально поставляемый шрифт с кириллицей.
- **ESLint, Prettier** — проверка и форматирование кода.
- **Playwright** — браузерная проверка сценариев и сохранение скриншотов.

Точные версии зафиксированы в `frontend/package.json` и `frontend/package-lock.json`. Для воспроизводимой установки используйте `npm ci`.

## Настройка и запуск frontend

Нужны **Node.js 22.12+** и **npm**. Проект проверен на Node.js 24.11.1. На первой лабораторной серверная часть, база данных и переменные окружения не требуются.

В PowerShell из корня репозитория:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173**. Сервер останавливается сочетанием `Ctrl+C`. Порт 5173 должен быть свободен: `strictPort` не позволяет незаметно запустить приложение на другом порту.

На Windows команды используют `npm.cmd`, чтобы не менять политику выполнения PowerShell. В Linux/macOS и обычной командной строке можно использовать `npm` вместо `npm.cmd`.

### Сборка и предпросмотр

```powershell
npm.cmd run build
npm.cmd run preview
```

Сборка проходит проверку TypeScript и сохраняется в `frontend/dist`. Предпросмотр доступен на **http://127.0.0.1:4173**. При будущем размещении на отдельном веб-сервере необходимо возвращать `index.html` для клиентских маршрутов.

### Проверки

```powershell
npm.cmd run lint
```

Для браузерных проверок можно использовать установленный Google Chrome:

```powershell
$env:PLAYWRIGHT_BROWSER_CHANNEL = 'chrome'
npm.cmd run test:e2e
```

Если Chrome не установлен, используйте Chromium Playwright:

```powershell
npm.cmd exec playwright -- install chromium
Remove-Item Env:PLAYWRIGHT_BROWSER_CHANNEL -ErrorAction SilentlyContinue
npm.cmd run test:e2e
```

Playwright автоматически запускает сервер Vite или использует уже запущенный сервер на порту 5173. Семь проверок охватывают:

- все переходы, прямое открытие маршрутов, обновление страницы и историю браузера;
- переходы из карточек семьи и фильтры;
- отметку приёма, её отмену, обновление напоминаний и списка врача, сброс после перезагрузки;
- демонстрационные переключатели напоминаний;
- выбор человека в списке врача и вид для печати;
- отсутствие горизонтального переполнения страницы на мобильном экране и работу меню;
- неизвестный маршрут и возврат к расписанию.

Форматирование: `npm.cmd run format`. Отчёты, трассировки, зависимости и сборка исключены из Git через `.gitignore`.

**Проверено 07.10.2026:** production-сборка и ESLint проходят; все семь браузерных сценариев выполнены успешно. После визуальных правок повторно проверены мобильная верстка и печатный вид. Сохранены девять PNG и одностраничный пример PDF.

## Структура проекта

```text
frontend/
  src/
    app/                # маршруты, провайдеры, общая тема, оболочка и стили
    pages/              # основные экраны и страница 404
    entities/           # типы и демонстрационные данные предметной области
    features/demo/      # состояние демонстрационных отметок приёма
    shared/             # общие компоненты и работа с фильтром человека
    main.tsx            # точка входа и локальные шрифты
  e2e/                  # проверки сценариев и создание скриншотов
  public/               # favicon
  playwright.config.ts
docs/
  screenshots/          # все экраны, мобильные версии и печатный вид
  doctor-list-example.pdf
```

Это начальная модульная структура. При развитии проекта данные и действия можно отделить от демонстрационного источника без изменения набора основных экранов.

### Демонстрационные данные и ограничения этапа

В макете используются три вымышленных человека, пять лекарств и шесть приёмов за **7 октября 2026 года**. Дата фиксирована для воспроизводимой демонстрации. Два утренних приёма изначально отмечены как принятые. Названия, дозы и курсы служат примерами интерфейса.

Отметки работают только в памяти вкладки и сохраняются при переходах между экранами; после обновления возвращаются исходные данные. Переключатели напоминаний показывают состояние макета и сбрасываются при уходе с экрана. Уведомления браузера, системные напоминания, постоянное хранение, создание и редактирование назначений, вход и регистрация относятся к будущим этапам.

Приложение не рассчитывает медицинские назначения. На будущих этапах пользователь будет вносить назначенное врачом расписание.
